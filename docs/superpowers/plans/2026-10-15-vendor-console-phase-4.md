# Vendor Console Phase 4 (Reminders and Owner Reports) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner gets an e-mail for every issued license and a weekly summary; the owner and the responsible sales person get expiry reminders at 90, 60 and 30 days; a "Renew" button on the license list prefills a new request from an old license.

**Architecture:** E-mail goes through a database outbox (`mail_outbox`). A database trigger writes the issuance e-mail in the same statement that inserts the license, so no client can issue without the owner being notified. A separate run-once command (`vendor-console notify run`, meant for cron or a systemd timer) creates reminders and the weekly summary, then sends everything pending over SMTP (STARTTLS required). The command connects as its own login, member of a narrow role `vendor_notifier`.

**Tech Stack:** Go 1.27, `pgx/v5`, `net/smtp` + `crypto/tls` (no new dependency), `html/template` for the renew prefill, testcontainers PostgreSQL 16 via `vpgtest`, an in-test SMTP server.

**Spec:** `docs/superpowers/specs/2026-10-15-vendor-console-design.md` (section 7 "Owner visibility", section 10 phase 4)

## Global Constraints

- Branch `vendor-console-notify`, cut from `master`. Merged into `master` locally (fast-forward) at the end; never pushed.
- `alice` (the product binary) must not link anything under `alice/internal/vconsole/...` or `alice/cmd/vendor-*` (the release-binary test already covers `vconsole/...`; extend it for any new package).
- `internal/vconsole/...` imports only the platform and (where allowed) `alice/internal/license/...` from the product. No import of `alice/internal/notify`.
- No SMTP password, database URL or token in logs, errors or e-mail bodies. E-mail bodies contain no license file content and no installation ID beyond the first 8 characters.
- SMTP: STARTTLS (or implicit TLS on port 465) with certificate verification is required, unless the server host is loopback; plain-text AUTH is never sent over an unencrypted connection. Timeouts: dial 10 s, whole message 30 s.
- Header injection: subjects and addresses never contain CR or LF; refused, not stripped.
- The audit chain is extended for every new state change that matters (settings changed, reminders created are not audited individually; settings and web-user e-mail changes are).
- Go style: errors lower-case and wrapped with `%w`, no `panic`, comments say why. Time comes in as a parameter (`now time.Time`); no `time.Now()` in library code.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; commit with `git -c user.name="Eren Altan" -c user.email="erenaltan@gmail.com" commit ...`.

## Rulings (open item O5 and friends)

1. **E-mail provider (O5):** provider-neutral SMTP, configured by environment: `VENDOR_SMTP_ADDR` (`host:port`), `VENDOR_SMTP_USER`, `VENDOR_SMTP_PASSWORD`, `VENDOR_SMTP_FROM`. Any provider works (a transactional service or the company's mail server). The sender address is the operator's choice.
2. **Who is "the sales owner" of a license:** the person who made the request (`license_requests.requested_by`). For a web user (`web:<name>`) the address is `web_users.email`; for a database login there is no address, so only the owner is told.
3. **Owner address and settings:** a `vendor_settings` table (key/value) holding `owner_email`, `weekday_summary_day` is not needed: the weekly summary is generated by the run when more than 7 days passed since the last one (`summary` row in `vendor_settings`), so the schedule is the timer's job. Settings are changed by the owner only and audited.
4. **Odd activity** (spec section 7): a license issued between 22:00 and 06:00 in the time zone `vendor_settings.timezone` (default `Europe/Istanbul`), or more than 5 licenses issued by one signer in one local day. Both numbers are constants in the code, listed in the weekly e-mail as "unusual".
5. **Renewal draft:** not a stored draft row. The license list gets a "Renew" link to `/requests/new?renew=<license-id>` that prefills customer, installation, targets, features and a start date equal to the old end date, for the person to review and submit. Reminders link to it.
6. **Reminder catch-up:** if a license is found already inside a threshold that was never sent (the timer did not run, or the license was issued 20 days before its end), only the most urgent unsent threshold is sent, and the less urgent ones are recorded as sent so they never fire late.

## Review Focus

- A license issued directly through SQL by a signer login (not through `vendor-console issue`) still produces the owner e-mail (the trigger, not the client, writes it). Pinned in Task 1.
- Two `notify run` processes at the same time send each message once. Pinned in Task 3.
- SMTP down or rejecting: the message stays pending, attempts and last error are recorded, the next run retries; after 10 attempts it is marked failed and shows in the summary. Pinned in Task 3.
- A license revoked or already replaced by a correction before its 30-day reminder: no reminder. Pinned in Task 4.
- A license with a very long customer name or an address with CR/LF in it: refused or truncated safely, never a header line. Pinned in Task 2.
- Weekly summary on a quiet week still goes out (it proves the system is alive). Pinned in Task 5.
- The renew prefill with an unknown or foreign license ID: 404, and no data of a license leaks into the form of another customer. Pinned in Task 6.
